# PCB design

Use the installed `pcb.design.*` tools for the user's design. Harness prepares the pinned PCB environment automatically. Start with `project_status` to inspect supplied CAD, current checks and missing evidence. An empty workspace is a valid new design: use `new_project`, then record the user's dimensions, connectivity, constraints and applicable analyses with `set_requirements`. Existing projects must be inspected before editing. No seed board, fixed evaluation task, evaluator or submission is required.

Follow the requested scope: inspection, focused repair, simulation or full delivery. Explain material choices with an engineering reason and the check that will test them. Finish a focused request after its checks and factual report; export only when requested. A tool's successful execution records an operation, not a design PASS. Report actual ERC, DRC, parity, applicable simulation and hardware qualification separately. Missing models, measurements or coverage remain UNKNOWN within the relevant scope.

The maintained tools and detailed references are reused from the pinned upstream design runtime. Call `inspect_tool(name)` for the current argument/output contract. Discover reference names with `pcb.design.list_references` and empty arguments `{}`, then read the relevant document with `pcb.design.read_reference` and arguments such as `{"name":"tools.md","start_line":1,"max_lines":180}`. `start_line` starts at 1; `max_lines` accepts 1–400 and defaults to 180. Continue from the returned `end_line + 1` when it is below `total_lines`. Every reference filename below refers to this tool interface, so it remains available when this Skill is copied into a session by itself.

The Pack preserves the original `pcb-design-e2e` Skill and its resources as an attributed, hash-verified source snapshot. Its fixed public tasks and structured submission instructions describe optional evaluation integrations. In this product, the user's design brief determines the work, `spec.json` records editable design intent, and candidate-authored analyses are reported as diagnostics with explicit assumptions. Separately bound requirements, when supplied by a trusted integration, remain authoritative and cannot be waived by edits.

1. Inspect current files and checks. Select explicit project geometry rules via `set_requirements(section="constraints",value={board_rules:{clearance_mm,track_mm,via_mm,drill_mm,edge_mm,hole_mm}})` before PCB generation; all six values must be positive mm and via diameter must exceed drill. Derive them from the user’s stated needs or a clearly explained prototype choice; there are no hidden factory defaults. Create intent only for a new design. Keep existing CAD, copper, object identities and dependencies during repairs.
2. Research parts; inspect canonical symbol pins and sourced MPN facts before connecting them. Use `prepare_component` → `qualify_component` → `install_component` for missing parts. CAD drafts and library names do not establish electrical suitability. Read `tools.md` and `standards.md`.
3. Generate or edit the schematic. Verify ERC, exported netlist/intent parity and symbol/footprint pin mapping. Drawing moves and field poses differ from connectivity changes; rerun the affected checks after wire or topology edits. Read `verification.md`.
4. Declare and run applicable analyses with real models, stimuli, assertions and revision binding. `run_analysis` uses declared intent when no external requirements are bound; `basis=candidate` explicitly requests design diagnostics. Report each analysis result and limitation. Read `analysis.md` and `numerical.md`.
5. Generate the PCB after schematic checks. If electrical coverage is incomplete, state the user's authorized prototype/diagnostic scope in `cad_only_reason`; an actual failed check still blocks generation. Place footprints using observed pads and board geometry. Read `layout.md`.
6. Route or repair using atomic native operations. Query current targets and complete affected-net copper before mutations; follow revision-bound pagination. Fill zones, run DRC and schematic/PCB parity, and inspect introduced findings. Keep unaffected copper. Read `advanced-cad.md` and `agent-loop.md`.
7. Return the requested CAD, reports, views or exports. `save_project_copy` retains unfinished work without acceptance claims. `export_project` produces a freshly checked CAD/Gerber/drill/BOM/placement bundle and may block on unresolved verification. Do not invent manufacturing readiness from a file export.

For local repair, distinguish measured facts from hypotheses. Locate the failing reference, pin, net or UUID with its sheet/layer and coordinates. Partial observations cannot prove objects absent; follow `next_call`. Refresh stale findings after edits. A smaller error count is insufficient when connectivity was removed. Preserve original design constraints and failed evidence. Use retained reports through `project_status(check_stage=...)` instead of rerunning unchanged checks merely to read them.

After interruption, inspect `operation_outcome` and the current CAD before editing again. `CHANGED_REVIEW_REQUIRED` means files changed despite failure; never replay that mutation blindly. Harness owns cancellation, container cleanup and session recovery. Native runtime source/schema/version checks, process-held workspace locks and operation receipts remain enforced.

Use `view_design` for revision-bound native images. Visual review requires actual image blocks delivered by the host to the model; an image hash or forwarded transport receipt alone is insufficient. Text-only runs must rely on measured geometry. Partial views cannot qualify other sheets, layers or assembly geometry.

`run_python` is a bounded read-only calculator for candidate files and reports. It cannot edit CAD, spawn processes, use the network or inspect controller/evaluator internals. Missing public operations are capability gaps. Geometry does not prove circuit function, impedance, EMC or compliance; a behavioral SPICE model does not qualify a commercial device or all operating corners. Factory adaptation and ordering are outside this capability.
